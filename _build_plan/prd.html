whatsapp_waha

A Home Assistant integration that connects to your self-hosted WAHA (WhatsApp HTTP API) server on your Proxmox LXC, so Home Assistant can send and receive WhatsApp messages natively — with human-like pacing so your secondary number doesn't get flagged, and a notify target gate-pin and other automations can use for alerts.

Python Home Assistant custom integration WAHA REST API HACS-ready (later)

What the integration does

  • Connect to your WAHA server

    A setup screen for host, port, API key and session name, with clear errors and automatic session creation if one doesn't exist yet.

  • Automatic, signed webhook wiring

    Home Assistant registers itself with WAHA — no pasting URLs or editing the LXC — and signs the connection so nothing else on your network can fake a message.

  • Link your WhatsApp number

    Scan a QR code shown right in Home Assistant, or use a texted pairing code instead, to link your secondary WhatsApp number.

  • Send from Home Assistant

    Send a text, image, or other message type to a phone number or a WhatsApp group by name, from any automation.

  • Receive messages and trigger automations

    An incoming WhatsApp message can trigger a Home Assistant automation, with sender and text available to it.

  • Human-like, rate-limited sending

    Normal messages show a typing pause and pace themselves like a person; urgent alerts use a faster lane so they still arrive promptly.

  • Notify service for alerts

    A standard notify target any automation or add-on — including gate-pin — can send a title and message to.

Already provided by Home Assistant

  • Setup-screen (config flow) UI
  • Webhook HTTP endpoint infrastructure
  • Automation engine to react to events
  • Notify-service framework
  • Sensor / entity framework
  • Repair-issue prompts
  • Diagnostics download

Out of scope (v1)

  • A Home Assistant add-on that runs WAHA itself — WAHA stays on your own Proxmox LXC, so a Home Assistant reboot never touches your WhatsApp session.
  • Publishing to HACS — deferred; the folder layout is kept ready for it, but it isn't done in v1.
  • Catching up on messages missed while Home Assistant was offline — WAHA has no message-replay capability to build this on.
  • Linking via WhatsApp's newer "passkey" method — falls back to WAHA's own dashboard, which already supports it.
  • Any changes to gate-pin — it plugs in through its existing notify setting, unchanged.
  • A way to fully bypass the human-like sending pace — it can be loosened, not switched off, to protect your number from being flagged.
  • A chat-history view inside Home Assistant — replying is a fresh "send", not a threaded conversation UI.

Milestones

1

Connect, link & receive

Gets a WAHA connection into Home Assistant, wired for inbound messages: connect, self-register the webhook, scan the QR, and see incoming messages trigger automations.

What gets built

  • Setup screen connecting to your WAHA server, creating the session if needed
  • Automatic, signed webhook registration — no manual URL pasting
  • QR code in Home Assistant to link your number, plus a pairing-code fallback
  • A sensor showing whether the WhatsApp session is connected
  • Incoming messages trigger Home Assistant automations

Not in this milestone

  • Sending anything out
  • The human-like pacing / anti-ban queue
  • The notify service for gate-pin and other add-ons
  • Extra message types (images, polls, etc.)

Done when: you can open the integration, scan the QR with your secondary phone, watch the sensor turn "connected", send yourself a test WhatsApp message, and see it trigger a test automation in Home Assistant.

2

Send safely & notify

Adds sending, paced to protect your number, plus the notify target gate-pin and other automations will use for alerts.

What gets built

  • Sending text, images and other message types, to a number or a group by name
  • Human-like pacing on normal sends, a faster lane for urgent alerts, and a per-chat hourly cap
  • A standard notify target other automations and add-ons (including gate-pin) can send to
  • Diagnostics, reconnect handling, and repair prompts for problems like an expired link

Not in this milestone

  • Publishing to HACS
  • Editing or un-sending a message after it goes out

Done when: you can call a send action from Developer Tools and see it arrive on WhatsApp with a visible typing pause, point gate-pin's notify setting at the new notify target and see a lockout alert arrive promptly, and trigger a deliberate WAHA disconnect to see the repair prompt appear.
